What the system does

QuickBooks Desktop runs on one Windows computer and only people sitting at that computer can use it. The Synex QB Portal keeps a live copy of the QuickBooks company file on a web server, so staff can work from any browser or phone while QuickBooks stays the system of record.

  • Read everything: all customers, vendors, items, accounts and transactions, refreshed from QuickBooks every minute.
  • Write safely: create, edit, delete and void records. Each change waits for approval (unless the user has direct-write rights) and is then written into QuickBooks on the next sync.
  • Work faster than in QuickBooks: search across everything, aging, customer and vendor overviews, reorder alerts, bulk import from Excel, bulk PDF and e-mail, saved views.
  • Control access: roles per module, per-company access, two-step sign-in and a full audit log.
QuickBooks remains the master. The portal never changes QuickBooks data on its own. Every write is a QuickBooks request that QuickBooks itself validates; if QuickBooks rejects it, the change shows as failed with QuickBooks' own message.

How it works

QuickBooks Desktop cannot be reached over the internet directly. Intuit's QuickBooks Web Connector (QBWC), installed on the QuickBooks computer, calls the portal every minute over HTTPS and asks "is there any work?". The portal answers with qbXML requests (read changes, write approved changes, run reports) and QBWC passes the answers back.

One sync cycle

ConnectWeb Connector signs in with the company's Web Connector user and password.
Check the fileThe portal confirms the open company file is the one registered for that company, otherwise it stops.
Read changesAll record types modified since the last sync are read in one batched request.
WriteApproved changes are sent to QuickBooks one by one; each result is saved.
ReportsReports that users asked for are run and stored.

The first sync of a company reads everything (transactions from the last 365 days). After that each sync reads only what changed, so a normal sync takes a few seconds. Deleted QuickBooks records are detected and hidden. Features that a company file does not have (for example multi-currency) are detected automatically and switched off for that company.

Reports

36 QuickBooks reports run inside QuickBooks itself, so the numbers match QuickBooks exactly: 14 general reports (Profit & Loss, Balance Sheet, Trial Balance, customer and vendor balance summaries and more), 17 detail reports and 5 aging reports. Results can be exported to Excel.

Workflows that follow QuickBooks

  • Estimate or sales order → Create invoice (pre-filled).
  • Purchase order → Receive items → item receipt → Convert to bill.
  • Received payments and bill payments pick only open invoices or bills of the chosen customer or vendor.
  • Custom fields from QuickBooks are shown on each record (read only).

Changes and approvals

Every create, edit, delete or void becomes an entry in the change queue with one of these states:

StateMeaning
pendingWaiting for someone with approve rights for that module.
queuedApproved (or made by a user with direct-write rights); goes to QuickBooks on the next sync, within about a minute.
doneQuickBooks accepted it; the QuickBooks reference number is saved.
failedQuickBooks refused it, with QuickBooks' reason. It can be fixed and retried, or discarded.
rejectedAn approver declined it, with a reason.

The approval inbox shows each change field by field ("Now in QuickBooks" against "Will become"), including line items, and allows approving several changes at once. Edits use QuickBooks' edit sequence, so a record changed in QuickBooks in the meantime is refused instead of overwritten.

Users, roles and access

Permissions are given per module (sales, purchasing, banking, accounting, inventory, lists) and per action: view, create, edit, delete, approve, and direct (write without approval). Extra permissions: reports.view, sync.run, users.manage, audit.view. Roles are edited in the portal; these five come built in:

RoleCan do
adminEverything, in every company, including users, roles, companies and the audit log.
accountantEverything in all six modules including approve and direct write, reports and sync; not users or audit.
salesView, create and edit sales; view lists; reports. Changes need approval.
purchasingView, create and edit purchasing; view inventory and lists. Changes need approval.
viewerRead only, all modules.

People sign in with their e-mail address or username and password, then a 6-digit code from Google Authenticator (or Microsoft Authenticator / Authy) when two-step verification is on. Each user gets 8 single-use recovery codes. An admin can reset a user's two-step verification when a phone is lost.

Multiple companies

Each Synex Group company is registered once in the portal with its own Web Connector user, password and .qwc file. Its data is kept separate, users are given access per company (admins see all), and people switch company from the top bar.

QuickBooks opens one company file at a time. Two companies on the same QuickBooks computer cannot sync in the same minute; the one whose file is not open reports "a different company file is open". Keep only the active company in Web Connector, or use a separate QuickBooks computer per company.

Security

Application

  • HTTPS only, with HSTS. Passwords stored as bcrypt hashes; authenticator secrets encrypted.
  • Two-step verification is required for admins and anyone who can approve or write directly. Until it is set up, they can only reach the Account page.
  • Wrong passwords lock the account for 15 minutes after 10 tries, and an address after 30. Wrong authenticator codes lock for 5 minutes after 5 tries.
  • Passwords: at least 10 characters with letters and numbers, not a common password, not containing the username.
  • Changing a password, a reset by an admin, deactivating a user or "Sign out on all other devices" ends all other sessions at once. Sessions otherwise last 8 hours.
  • Content Security Policy, frame blocking, no-sniff and referrer headers; fonts are served by the portal itself, so pages load nothing from other sites. API documentation is switched off.
  • Attachments limited to documents and pictures (PDF, images, Office, CSV, ZIP), 20 MB each.
  • Audit log of sign-ins (with address), failed sign-ins, every change, approval, export, e-mail and settings change.

Server

  • Firewall on; the database listens only inside the server.
  • fail2ban bans an address for 1 hour after 6 wrong SSH sign-ins.
  • Operating-system security updates install automatically; the web server hides its version.
  • Secrets live in a server file readable only by the portal's own system user.

After a server restart

Nothing has to be started by hand. Allow 2-3 minutes, then open the portal and check that "Synced … ago" in the top bar moves. Web Connector reconnects by itself; changes made in the meantime wait in the queue and are not lost.

Updating the portal

New versions are tested, committed to GitHub, copied to the server, built there and activated with a service restart, normally with under 10 seconds of downtime.

QuickBooks computer setup

  1. QuickBooks Desktop 2024 with the company file open, in multi-user or single-user mode.
  2. QuickBooks Web Connector 2.2 or later.
  3. In the portal: Companies → company → download the .qwc file.
  4. In Web Connector: Add an application → choose the .qwc → allow access in QuickBooks ("Yes, always; allow access even if QuickBooks is not running") → enter the company's Web Connector password → tick Auto-Run.
  5. Keep the computer on and signed in; if it sleeps or Web Connector closes, the portal shows the last synced data and queues changes.

A step-by-step guide with screenshots is in the repository at docs/QUICKBOOKS_DESKTOP_SETUP.md.

QuickBooks record types are described once in a single registry (fields, field order required by Intuit, which can be created or edited). Lists, forms, import templates, Excel exports and qbXML requests are all generated from that registry, so supporting a new QuickBooks field means changing one place.

Testing and quality

  • 434 automated backend tests: every record type's read, create and edit request against Intuit's rules, the Web Connector conversation, approvals, imports, multi-company isolation, permissions, sign-in and two-step rules, security headers and the newer features.
  • End-to-end browser test: starts a throw-away copy of the portal, loads sample QuickBooks data through a simulated Web Connector, then opens every page, all 50 lists, every New form and import page, and fails on any script error or server error.
  • Both suites run before every release.
  • Tested against live data: Synex International (28,893 records on first sync); each list was compared with the database count.

Limits

  • Not real time: changes reach QuickBooks in about one minute, and only while the QuickBooks computer and Web Connector are running.
  • One file at a time per QuickBooks computer (see Multiple companies).
  • 13 record types cannot be edited through Web Connector; QuickBooks custom fields are read only.
  • Payroll, bank reconciliation, sales tax filing, budgets and closing the books stay in QuickBooks Desktop.
  • Large-data growth: aging and the daily summary load all open invoices and bills; fine at today's size, worth optimising past roughly 100,000 open documents.
